# Build notes

Decisions and shortfalls recorded while building Tie-Out.

## Foundations

- `Results` holds `meta`, `assumptions`, `totals`, `trace` and `scorecard` as plain JSON in `results.json`; frames are Parquet. `scorecard` is `None` or a dictionary.
- `Results.empty()` uses zero-column data frames; real column sets arrive with the modules that fill them.
- `DEFAULTS` in `tieout/assumptions.py` is a nested dictionary. Probability triples are `{"low", "base", "high"}` mappings; reference bands are `{"low", "high"}` mappings holding fractions (0.01 means 1%).
- Capture probabilities, discounts, caps, ramp values and other shares are validated to lie in [0, 1]; reference bands need 0 <= low <= high. Days, months and dollar defaults are not range-checked.
- `merge_overrides` deep-merges user overrides over the defaults and does not validate; callers run `validate` on the merged result.
- The CLI returns exit code 2 when an input file is missing (the PRD's blocking-error code), and 1 while the pipeline is not wired in.

## Vendor matching

- **V0 punctuation.** Apostrophes and periods are deleted ("O'Brien" -> "obrien", "S.A." -> "sa"); all other punctuation becomes a space ("Coca-Cola" -> "coca cola"). A dangling "and" left by legal-form removal ("Smith & Co" -> "smith") is dropped, and at least one token is always kept ("Ltd" stays "ltd").
- **V0 branch markers.** The `(plant|site|branch|store|dc|whse) <alphanumerics>` form is taken when it is in parentheses, or when the trailing token contains a digit or is a single letter ("Store #12", "Plant A"). Without that restriction "Acme Site Services" would lose "site services" and exact-match plain "Acme". The trailing `- <words>` form needs whitespace before the dash so hyphenated names are kept. Markers are peeled repeatedly ("Acme Corp - Chicago Plant 3" -> branch "chicago plant 3"). A dba alias's branch is used when the primary part has none.
- **V2 uses aliases, V4 does not.** Exact-name grouping uses the primary name and every dba alias. V4 scores distinct primary names only.
- **Rare token for small inputs.** "Fewer than 1% of distinct names" can never hold for a shared token when there are fewer than 200 names, so a token counts as rare when it appears in fewer than `max(1% of distinct names, 3)` names. That means a token shared by exactly two names always blocks. Prefix blocking uses `name[:4]` of the normalised name.
- **Guards.** The score is computed on the name with generic tokens removed. If nothing is left, the full normalised name is scored instead, and the weak-name cap (91) applies. The descriptor clash cap (74) takes precedence over the 91 caps. The `cdist` pre-filter uses the unguarded score with a 0.05 tolerance, and survivors are re-scored exactly by one scalar function, so fresh and cached runs see identical scores.
- **V2 split groups.** In a split group, each `(country, tax ID)` set of records is one unit, and every record with no comparable tax ID is a unit of its own. Representative pairs (smallest key per unit) between units go to review: as `vendor_sibling` when the two are tax-vetoed, otherwise as `vendor_match` at tier C. This also covers no-tax records reviewed against each other and same-name records from a different country. Taking "not merged automatically" literally, records with no tax ID in such a group are not merged even with each other.
- **V5 "every distinct name" test across two clusters.** When two multi-record clusters meet, every tested name on one side must score >= `review_threshold` against every tested name on the other side, and each record's own name counts as tested. Tested names come from V2 merges (only where the shared name is a record's primary name) and from both ends of a V4 merge. Names attached by tax ID, by dba alias or by a reviewer's approval are not tested. The test re-scores those few name pairs on the fly, including on the `cached_pairs` path.
- **Exact names are left to V2.** A record pair that already has a V1 or V2 row is never re-decided by V4, even when the V2 outcome was "review". Fuzzy similarity therefore cannot override a split decided on exact-name evidence.
- **Decisions.** Approved `vendor_match` pairs are applied after V1 and before V2 as forced merges. The reviewer overrides a tax-ID veto. Rejected `vendor_match` pairs act as cluster-level cannot-links for V2 and V4 (but not V1), so neither record can be pulled together with the other through a third record. A deferral counts as "no decision" for clustering and shows as `deferred` on a pair that would otherwise be pending. Approved siblings, together with any parent-table links, are grouped. The group's `parent_id` is the smallest `P:` parent in it, otherwise the smallest `legal_entity_id`. When a legal entity's members map to several table parents, the smallest is used.
- **Pair log.** `pairs` also holds the automatic V1/V2 merges (anchor = smallest key in the group, status `auto`) and V4 pairs vetoed below 92 (status `vetoed`), so the log explains every link. An extra column `score_detail` keeps the scoring evidence without the outcome sentence, and the `cached_pairs` path reads candidates from rows with `stage == "V4"`. A pending pair whose records end up in one legal entity through other evidence is marked `auto`. `vendor_map` gains an `evidence` column.
- **`vendor_map.stage`.** This is the strongest link a record took part in, ranked V1 > V2 > human > V4. A singleton with a parent-table link gets `V3` at tier A. Identifiers use at least five digits (`LE00001`).
- **Recall risk (not handled, per the PRD).** A truncated legal form at the 30-character cut ("... Corpor") is not in the legal-form list, so such names reach V4 with an extra token and often land in review. A typo inside a descriptor token ("Fastners") trips the one-descriptor cap of 91. Both cost recall, not precision. The PRD's descriptor and truncation rules were left unchanged; `evaluation/` should measure this.
